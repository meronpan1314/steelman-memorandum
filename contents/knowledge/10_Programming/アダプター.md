## 結論

アダプターは、異なるインターフェース同士をつなぐための変換役である。

既存の部品を、利用側が期待する形に合わせるために使う。

---

## 1. アダプターとは何か

アダプターは「変換器」。

身近な例では、電源プラグの変換アダプターに近い。

```text
利用側が期待する形 → アダプター → 既存部品
```

ソフトウェアでも、使いたいクラスやAPIの形が合わないことがある。

その差分を吸収するのがアダプター。

---

## 2. 何を解決するのか

例えば、アプリ側は以下の形で通知したい。

```java
interface Notifier {
    void send(String message);
}
```

しかし、外部ライブラリは別の形になっている。

```java
class MailClient {
    void sendMail(String body) {
        // メール送信
    }
}
```

このままだと直接差し替えにくい。

---

## 3. アダプターの例

```java
class MailNotifierAdapter implements Notifier {
    private final MailClient mailClient;

    MailNotifierAdapter(MailClient mailClient) {
        this.mailClient = mailClient;
    }

    @Override
    public void send(String message) {
        mailClient.sendMail(message);
    }
}
```

利用側は `Notifier` だけを見ればよくなる。

---

## 4. メリット

- 既存クラスを修正せずに使える
- 利用側のコードをシンプルに保てる
- 外部ライブラリへの依存を局所化できる
- テスト時に差し替えやすくなる

---

## 5. まとめ

- アダプターは形の違うもの同士をつなぐ変換役
- 既存コードや外部APIを利用側の期待する形に合わせる
- 依存の影響範囲を小さくできる
