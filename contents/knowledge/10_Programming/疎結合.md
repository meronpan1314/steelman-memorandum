title: 疎結合
date: "2026-05-02"

---

## 結論

疎結合とは、部品同士の依存が弱く、片方を変更してももう片方への影響が小さい状態である。

変更しやすく、テストしやすい設計につながる。

---

## 1. 疎結合とは何か

クラス同士が具体的な実装に強く依存せず、インターフェースや外部から渡された依存を使う状態。

```java
class UserService {
    private final UserRepository repository;

    UserService(UserRepository repository) {
        this.repository = repository;
    }
}
```

`UserService` は自分で `UserRepository` を生成していない。

外部から渡してもらうことで、依存を差し替えやすくしている。

---

## 2. メリット

- 変更に強い
- テストしやすい
- 部品を再利用しやすい
- 責務を分けやすい

疎結合にすると、コードの入れ替えや拡張がしやすくなる。

---

## 3. DIとの関係

DIは、疎結合を実現する代表的な方法。

依存するオブジェクトをクラス内で生成せず、外部から渡してもらう。

```java
class OrderService {
    private final Notifier notifier;

    OrderService(Notifier notifier) {
        this.notifier = notifier;
    }
}
```

これにより、通知方法を差し替えやすくなる。

---

## 4. 注意点

疎結合を意識しすぎると、抽象化が増えすぎて読みにくくなることがある。

小さな処理まで無理にインターフェース化する必要はない。

「変更されそうなところ」「外部依存があるところ」を中心に考える。

---

## 5. まとめ

- 疎結合は部品同士の依存が弱い状態
- 変更やテストに強くなる
- DIやインターフェースで実現しやすい
- 抽象化しすぎには注意する
