## 結論

密結合とは、部品同士の依存が強く、片方の変更がもう片方に影響しやすい状態である。

変更に弱く、テストもしづらくなる。

---

## 1. 密結合とは何か

あるクラスが、別の具体的なクラスに強く依存している状態。

```java
class UserService {
    private UserRepository repository = new UserRepository();
}
```

この場合、`UserService` は `UserRepository` を自分で生成している。

そのため、別の実装に差し替えにくい。

---

## 2. 何が問題なのか

密結合になると、以下の問題が起きやすい。

- 変更の影響範囲が広がる
- テスト用の部品に差し替えにくい
- 再利用しにくい
- クラス同士の責務が曖昧になる

---

## 3. 例

メール送信処理を直接呼び出している場合。

```java
class OrderService {
    private MailSender mailSender = new MailSender();

    void order() {
        mailSender.send();
    }
}
```

この設計だと、メール送信の仕組みを変えたいときに `OrderService` も影響を受ける。

---

## 4. 改善の方向

インターフェースやDIを使い、具体実装への依存を弱める。

```java
class OrderService {
    private final Notifier notifier;

    OrderService(Notifier notifier) {
        this.notifier = notifier;
    }
}
```

これにより、メール通知・Slack通知・テスト用通知などへ差し替えやすくなる。

---

## 5. まとめ

- 密結合は部品同士の依存が強い状態
- 変更やテストに弱くなる
- 具体クラスを直接生成すると密結合になりやすい
- インターフェースやDIで依存を弱められる
