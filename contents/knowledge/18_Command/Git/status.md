## 結論

`git status` は、作業ツリーとステージングエリアの状態を確認するコマンド。

Gitで作業するときは、変更前、変更後、コミット前に何度も見る基本コマンド。

## 基本形

```bash
git status
```

現在のブランチ、変更されたファイル、ステージ済みのファイル、未追跡ファイルを確認する。

## よく使う形

```bash
git status --short
```

状態を短い形式で表示する。

```bash
git status -sb
```

短い形式に加えて、現在のブランチ情報も表示する。

## 表示の見方

```text
 M contents/example.md
A  contents/new.md
?? memo.md
```

左側の記号で状態が分かる。

| 表示 | 意味 |
| --- | --- |
| ` M` | 変更済みだが、まだステージしていない |
| `M ` | ステージ済みの変更がある |
| `A ` | 新規ファイルがステージ済み |
| `D ` | 削除がステージ済み |
| `??` | Gitがまだ追跡していない新規ファイル |

## 使いどころ

- どのファイルを変更したか確認する
- コミット前に余計な変更が混ざっていないか確認する
- `git add` したファイルと、まだしていないファイルを見分ける
- 今いるブランチを確認する

## 注意点

`git status` は状態を表示するだけなので、ファイルやコミット履歴は変更しない。

コミット前は、`git status` と `git diff` をセットで見ると事故が減る。
